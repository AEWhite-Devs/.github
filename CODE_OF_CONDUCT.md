# Code of Conduct

## Our Commitment

AEWhite Devs is committed to maintaining a professional, respectful, collaborative, and inclusive environment for everyone participating in our projects and communities.

We expect all contributors, employees, collaborators, maintainers, and community members to interact professionally and respectfully.

## Expected Behavior

Participants are expected to:

* Communicate respectfully and professionally.
* Provide constructive technical feedback.
* Respect differing opinions, experiences, and approaches.
* Focus discussions on ideas, code, design, architecture, and project objectives rather than individuals.
* Accept constructive criticism professionally.
* Help maintain a productive working environment.
* Respect the privacy and confidentiality of other participants.
* Follow project contribution, security, and development guidelines.
* Report problems responsibly when necessary.

Technical disagreements are normal and encouraged when they help improve the project. They should be supported by reasoning, evidence, testing, documentation, or clearly explained trade-offs.

## Unacceptable Behavior

The following behavior is not acceptable:

* Harassment, intimidation, or personal attacks.
* Discrimination or derogatory comments.
* Threats or encouragement of harmful behavior.
* Repeatedly disrupting technical discussions.
* Deliberately obstructing the work of other contributors.
* Publishing private or confidential information without authorization.
* Sharing credentials, secrets, internal infrastructure information, or private source code without authorization.
* Attempting to bypass project security policies or access controls.
* Malicious changes to repositories, infrastructure, applications, or project data.
* Knowingly introducing vulnerabilities, backdoors, malware, or other harmful functionality.
* Abuse of administrative privileges.
* Any conduct that would reasonably be considered inappropriate in a professional environment.

## Technical Discussions

Disagreement over implementation decisions is not considered misconduct.

Participants are encouraged to challenge:

* Architectural decisions.
* Implementation approaches.
* Code quality.
* Security assumptions.
* Performance decisions.
* Product requirements.
* Technical debt.
* Testing strategies.

However, criticism must remain focused on the work rather than the person responsible for it.

For example:

**Acceptable:**

> This implementation introduces unnecessary coupling between these modules. I recommend separating them because...

**Not acceptable:**

> Whoever wrote this clearly has no idea what they are doing.

## Confidentiality

Participants with access to private AEWhite Devs resources must protect confidential information.

Confidential information may include:

* Private source code.
* Credentials and API keys.
* Infrastructure information.
* Internal documentation.
* Security reports.
* User or customer information.
* Business information.
* Financial information.
* Unreleased product information.
* Internal discussions and decisions.

Access to confidential information does not grant permission to disclose or reuse it outside its intended purpose.

## Security Issues

Potential security vulnerabilities must be handled according to the AEWhite Devs Security Policy.

Security vulnerabilities should **not** be disclosed through public issues, discussions, or other public channels.

Please refer to `SECURITY.md` for the responsible disclosure process.

## Enforcement

Project maintainers and organization administrators are responsible for interpreting and enforcing this Code of Conduct.

Depending on the circumstances, violations may result in:

1. A private warning.
2. Removal of inappropriate content.
3. Temporary restriction of participation.
4. Removal of repository, project, or organization access.
5. Permanent removal from AEWhite Devs projects or communities.
6. Additional administrative or legal action when appropriate.

The response will depend on the severity, context, and frequency of the behavior.

## Reporting a Problem

Conduct-related concerns may be reported privately to:

**[contact@aewhitedevs.com](mailto:contact@aewhitedevs.com)**

Security-related concerns should instead be reported to:

**[security@aewhitedevs.com](mailto:security@aewhitedevs.com)**

Reports will be reviewed as privately as reasonably possible.

## Scope

This Code of Conduct applies to participation in AEWhite Devs spaces, including:

* GitHub repositories.
* Issues and pull requests.
* Code reviews.
* Discussions.
* Project management systems.
* Internal communication channels.
* Meetings.
* Development and testing environments.
* Community spaces officially associated with AEWhite Devs.

It may also apply when an individual is officially representing AEWhite Devs in another environment.

## Project Integrity

Everyone contributing to AEWhite Devs projects shares responsibility for protecting the integrity of the software and development process.

Contributors should not intentionally:

* Circumvent required reviews.
* Manipulate tests or CI results.
* Conceal known defects.
* Falsify development records.
* Misrepresent completed work.
* Introduce undocumented production changes.
* Use project resources for unauthorized purposes.

Problems and mistakes should be reported openly so they can be corrected.

## Changes to This Policy

AEWhite Devs may update this Code of Conduct as the organization, projects, and community evolve.
