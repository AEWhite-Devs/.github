# Support

This document explains how to request help or report problems related to AEWhite Devs projects.

## General Support

For general questions, project-related inquiries, or non-security concerns, contact:

**[contact@aewhitedevs.com](mailto:contact@aewhitedevs.com)**

When requesting support, please include enough information to understand the issue or request.

Useful information may include:

* A clear description of the problem.
* The affected application, repository, or service.
* Steps to reproduce the issue.
* Expected behavior.
* Actual behavior.
* Application or version information.
* Device or operating system.
* Screenshots or recordings when relevant.
* Sanitized logs when available.

Do not include credentials, access tokens, API keys, private keys, recovery codes, or other sensitive information.

## Bugs

Reproducible software defects should normally be reported using the repository's **Bug Report** issue form.

Before opening a new bug report:

* Search existing issues.
* Confirm the issue has not already been reported.
* Collect the minimum steps necessary to reproduce it.
* Remove sensitive information from logs and screenshots.

## Feature Requests

New features and product improvements should normally be submitted using the repository's **Feature Request** issue form.

Feature requests should explain:

* The problem or opportunity.
* Who benefits from the change.
* The expected value.
* The proposed behavior.
* Relevant use cases.

Whenever possible, describe the problem before describing a specific implementation.

## Security Vulnerabilities

**Do not report security vulnerabilities through public GitHub Issues, Discussions, or Pull Requests.**

Security vulnerabilities should be reported privately to:

**[security@aewhitedevs.com](mailto:security@aewhitedevs.com)**

See [SECURITY.md](SECURITY.md) for the responsible disclosure policy.

## Private Repositories

Access to private AEWhite Devs repositories is limited to authorized members and collaborators.

If you believe you require access to a private repository, contact the appropriate project maintainer or organization administrator.

Repository access should only be granted when required for the contributor's responsibilities.

## Development Support

Questions about implementation, architecture, tests, Pull Requests, or repository-specific behavior should preferably be discussed in the relevant:

* GitHub Issue.
* Pull Request.
* Project discussion.
* Internal development channel.

Keeping technical discussions attached to the relevant work helps preserve project context and decisions.

## Infrastructure Issues

Infrastructure-related incidents or problems should be reported to the responsible infrastructure team through the approved internal communication channel.

Examples include:

* Deployment failures.
* CI/CD failures.
* Service outages.
* Database availability problems.
* DNS issues.
* Monitoring alerts.
* Backup failures.
* Internal networking problems.

Sensitive infrastructure information must not be posted in public repositories or public issues.

## Account and Access Problems

For problems involving:

* Repository permissions.
* Organization access.
* Team membership.
* Authentication.
* Lost access.
* GitHub permissions.

contact an AEWhite Devs organization administrator.

Never share passwords, authentication codes, recovery codes, or private keys when requesting assistance.

## Response Times

AEWhite Devs does not guarantee a specific response time for general support unless otherwise agreed.

Issues affecting:

* Security.
* Production availability.
* Data integrity.
* Authentication.
* Payments.
* Critical platform functionality.

may receive higher priority.
